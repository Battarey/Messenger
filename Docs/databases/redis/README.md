# Структура данных и ключи Redis

Redis выступает в роли сверхбыстрого in-memory хранилища и Pub/Sub брокера, обеспечивающего работу в реальном времени, кэширование горячих данных, сессий и очереди фоновых задач.

Все ключи в Redis структурированы с использованием префиксов для исключения коллизий и упрощения администрирования.


## Сецификация ключей Redis

| Префикс ключа | Тип данных Redis | TTL (Время жизни) | Описание и формат значения |
| :--- | :--- | :--- | :--- |
| `session:{session_id}` | **String (JSON)** | 24 часа (продлеваемый) | **Горячий кэш активных сессий бэкенда.**<br>Содержит JSON с основными данными сессии для мгновенной валидации JWT без обращения к PostgreSQL:<br>`{"user_id": "uuid", "device_info": "...", "expires_at": "..."}` |
| `presence:{user_id}` | **String** | 3 минуты | **Статус активности пользователя (Presence).**<br>Содержит строковое значение текущего статуса: `"online"`, `"away"`. Обновляется клиентом по Heartbeat-пингу каждые 60 секунд. Если пинги прекращаются, ключ сгорает, переводя пользователя в оффлайн. |
| `qr:{token_hash}` | **String** | 5 минут | **Авторизация по QR-коду.**<br>Используется для связывания сессии браузера и мобильного приложения.<br>1. При генерации QR: `qr:hash -> "pending"`<br>2. При сканировании смартфоном: `qr:hash -> "user_id:<uuid>"`<br>3. После подтверждения входа: удаляется или заменяется на JWT. |
| `email_verify:{email}` | **String** | 10 минут | **Одноразовый код подтверждения (OTP).**<br>Содержит случайно сгенерированный 6-значный код верификации почты при регистрации или входе: `"739281"`. |
| `rate_limit:{action}:{id}` | **String (Counter)** | 1 минута | **Ограничение частоты запросов (Rate Limiting).**<br>Счетчик запросов к чувствительным эндпоинтам бэкенда (например, `rate_limit:email_verify:user@mail.com`). Запросы отклоняются, если счетчик превышает установленный лимит за 1 минуту. |
| `arq:queue:*` | **Hash / List / ZSet** | Управляется `arq` | **Очередь фоновых задач (arq broker).**<br>Системные ключи библиотеки `arq` для планирования и выполнения асинхронных фоновых воркеров (отправка email, очистка устаревших сессий). |


## Каналы WebSocket Pub/Sub (События в реальном времени)

Redis Pub/Sub используется для обмена сообщениями и событиями между независимыми запущенными контейнерами бэкенда FastAPI, гарантируя моментальную доставку сообщений пользователям независимо от того, к какому именно серверу они подключены по WebSockets.

### Схема каналов:

#### 1. Канал конкретного чата: `chat:{chat_id}`
* **Назначение:** Трансляция новых сообщений, событий печатания (`typing`) и маркеров прочтения всем участникам активного чата.
* **Формат сообщения (JSON):**
  ```json
  {
    "event": "new_message",
    "data": {
      "message_id": "uuid",
      "sender_id": "uuid",
      "content": { "type": "text", "text": "Привет!" },
      "created_at": "2026-05-18T18:00:00Z"
    }
  }
  ```

#### 2. Персональный канал пользователя: `user:{user_id}`
* **Назначение:** Отправка системных уведомлений и событий, предназначенных конкретному пользователю (например, входящий звонок, системный пуш, обновление настроек, уведомление о блокировке).
* **Формат сообщения (JSON):**
  ```json
  {
    "event": "session_revoked",
    "data": {
      "session_id": "uuid",
      "reason": "Logged out from another device"
    }
  }
  ```

---

> [!TIP]
> **Параметры безопасности и кэширования:**
> * При кэшировании сессий в `session:{session_id}` используется стратегия **Lazy Loading** (ленивая загрузка): если ключа нет в Redis, бэкенд обращается к PostgreSQL, а затем записывает результат в Redis с TTL 24 часа. Это снижает требования к объему RAM в Redis.
> * Ключи лимитов запросов (`rate_limit:*`) всегда инкрементируются с помощью атомарной команды `INCR` и настраиваются с коротким TTL для автоматической разблокировки пользователей.
